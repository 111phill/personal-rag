# 我的知识库

一个面向个人工作与学习记录的知识工作台。

## 当前能力

- 按日期记录每日工作和学习内容
- 统一行动池：今日行动、明日行动和跨天承接共用一份数据，保留来源日期
- 周复盘：自动汇总行动与正文摘要，填写三项复盘并导出 Markdown
- 将笔记持久保存到 SQLite/D1
- 搜索标题和正文
- 从最近笔记快速切换日期
- 独立保存、编辑、软删除和归档收集箱内容
- 独立管理工作、学习和思考记录及其状态
- 将收集箱内容真正归档到今天或对应知识空间
- 右侧对话 Agent 可参考已保存的每日目标、工作、学习、灵感和收集箱记录，回答附可打开的来源
- 对话和消息保存在 D1，支持开启新对话、查看旧对话；小屏可从页头打开助手
- 响应式桌面与移动布局

## 本地运行

首次拉取代码后，在项目目录执行：

```powershell
npm ci --ignore-scripts
npm run db:init
npm run dev
```

打开 `http://localhost:3000`。`db:init` 创建缺失结构并显式导入旧行动，不删除原笔记。已有数据库升级前必须停止服务并备份，具体步骤见下文；不要在运行中的真实数据库上执行迁移。

### 升级到统一行动池

1. 停止本项目的开发或生产服务。
2. 完整复制 `.wrangler/state/` 到项目外的独立备份目录。它包含数据库，Git 提交不包含这些数据。
3. 执行 `npm run db:init`，确认命令成功，检查原文变化告警。
4. 重新启动服务并刷新所有已打开的标签页。旧客户端提交旧清单会被拒绝，避免覆盖新行动。

迁移为每篇笔记保留原始内容快照、哈希、导入标记和行动映射。结构化清单优先使用非空且唯一的旧 ID，其余使用固定快照中的位置；重复执行不会重复创建。中断后继续使用原快照，后续原文变化只告警，不覆盖行动。旧勾选项的实际完成时间未知，不伪造完成时间或迁移前的历史状态，也不计入精确历史完成分组。空白行不会导入。

验证或预览可设置 `PERSONAL_RAG_STATE_DIR` 为另一绝对目录，再执行 `db:init` 和 `dev -- --port 3001`，使用独立本地数据库；未设置时仍使用 `.wrangler/state/`。此变量须在初始化和启动时保持一致。

## 行动与周复盘

行动状态为待办、今日、延期、完成、放弃。待办没有安排日期；明日行动创建为延期并安排到明天，到期不自动改变状态。完成后撤销会恢复完成前的状态和安排日期，旧导入完成项则恢复为无安排待办。来源日期始终不变。

每日顶部直接展示待承接行动，按过期今日、旧待办、到期延期排序并去重，可快速纳入今天。今日行动使用单列清单，明日输入位于列表底部；已完成、已放弃和延期项收进折叠区。延期、放弃和查看来源位于行末三点菜单，日期不常驻展示。行动只能在现实今天操作；历史、未来日期的行动只读，正文仍可编辑。历史按上海时区日末的事件投影状态与安排，行动正文显示最新内容；无历史事件时通过勾选框提示历史状态未知。右侧助手默认关闭，由页头按钮打开抽屉。

周复盘默认本周，可切换历史周。行动按截止状态去重分为完成、未完成、延期、放弃，撤销完成单独标记；每日正文、独立工作和学习记录只展示摘要及来源。首次保存固定汇总快照，之后保存只更新本周收获、阻塞问题、下周重点；“更新汇总”显式替换快照并保留这三项内容。Markdown 导出包含当前显示的快照和输入内容，不调用 AI。

### 配置对话 Agent

在项目根目录创建不纳入 Git 的 `.dev.vars`，填写兼容 OpenAI Chat Completions 的服务地址、模型名和密钥：

```dotenv
AGENT_API_BASE_URL="https://your-provider.example/v1"
AGENT_MODEL="your-model"
AGENT_API_KEY="your-secret-key"
```

地址填 API 根路径，不含 `/chat/completions`；服务端会调用该路径。公网地址必须使用 HTTPS，本机模型服务可使用 `http://localhost` 或 `http://127.0.0.1`。生产部署时把这三个变量配置为服务端环境变量或密钥。修改配置后重启开发服务。未配置时仍可查看已有对话，发送入口会显示配置提示。

Agent 会把与问题相关的已保存记录片段发给所配置的模型服务。单次最多选取 10 条来源，每条最多 900 字；当前尚未保存的编辑内容不会参与回答。对话仅有读取记录的能力。回答中的来源编号经过服务端校验，点击来源可回到对应记录；若记录后来被删除，历史回答仍保留当时的来源标签，但目标可能无法再打开。

## 代码分工

- `app/page.tsx`：页面组合、导航与列表刷新。
- `components/`：每日编辑器、侧栏、小助手和各知识空间。
- `hooks/use-daily-note.ts`：连接浏览器请求、草稿备份与自动保存。
- `lib/note-session.ts`：保存队列、日期切换、冲突与恢复状态。
- `lib/daily-note.ts`：每日笔记字段、旧格式读取和 Markdown 导出。
- `db/note-store.ts`：每日笔记版本检查与事务归档；API 不再临时建表。
- `db/action-store.ts`、`hooks/use-action-pool.ts`：行动状态机、事件投影、幂等请求、冲突保护与浏览器草稿。
- `db/migrate-actions.ts`：旧清单固定快照、事务导入与稳定身份映射。
- `db/review-store.ts`、`components/weekly-review.tsx`：周汇总、固定快照、版本保存和导出。
- `db/agent-store.ts`、`lib/agent-context.ts`：对话持久化、历史记录检索与来源编号。
- `lib/agent-model.ts`、`app/api/agent/`：兼容接口调用与只读对话 API。
- `drizzle/`、`scripts/`：明确执行的结构迁移和旧数据维护。

## Git 版本备份与查看

项目已建立本地 Git 仓库，初始备份标签为 `backup/2026-10-14-initial`。每次完成一组改动后，在项目目录保存一个检查点：

```powershell
git status
git add -A
git commit -m "描述本次改动"
```

提交前检查 `git status`，确认要保存的文件。查看提交历史、当前未提交改动，以及相对初始备份的已提交改动：

```powershell
git log --oneline --decorate
git diff HEAD
git diff backup/2026-10-14-initial HEAD
```

只查看初始版本中的某个文件，无需切换当前工作目录：

```powershell
git show backup/2026-10-14-initial:app/page.tsx
```

初始 Git 历史另存为项目旁 `../personal-rag-backups/` 中的 `.bundle` 文件。可通过 `git clone <bundle文件路径> <新的目录>` 恢复这份初始备份；该文件不会自动包含后续提交。依赖、构建缓存、环境变量文件和本地笔记数据库不包含在 Git 备份中，笔记数据的备份方式见下节。

## 存储与冲突处理

笔记保存在项目的 `.wrangler/state/v3/d1/` 本地 SQLite/D1 数据库，不在 Git 中。备份时先停止本项目的开发服务，再完整复制 `.wrangler/state/` 到单独的备份目录。上传代码不等于备份笔记。

每日记录的新内容使用 `daily-note-v2` JSON 保存到原有 content 字段，仅包含正文和思考。行动独立保存，主记录和状态事件在同一事务内更新。原有笔记保持可读，只在之后保存时转成新版正文格式；迁移前禁止覆盖带旧清单的笔记。

每日正文停止输入约 800 毫秒后自动保存。行动内容在执行行动操作、点击页头保存或切换页面时保存；新增行动可点击加号或按回车。页头保存状态和离开前检查同时覆盖正文与行动。保存请求串行发送，数据库拒绝旧版本覆盖，行动请求可幂等重试。归档与来源状态更新在同一事务中完成，归档后刷新当前笔记。

每个浏览器标签页用 sessionStorage 暂存每日正文、行动及周复盘草稿，辅助同一标签页刷新后的恢复；它不是永久备份，关闭标签页后不能依赖它恢复内容。请看到“已保存”再关闭。旧版浏览器清单草稿不会静默丢弃，应先通过导出保留原文，再读取最新版本人工合并。工作、学习、收集箱记录仍在失去焦点时保存，失败时请保留页面并重试。

如果其他标签页或归档修改了同一天的笔记，页面会保留草稿并提示冲突。先导出草稿，再读取最新版本人工合并；不会自动用旧草稿覆盖新内容。工作、学习等独立条目的跨标签页编辑暂未加入版本合并。

旧版本曾在打开页面时自动补齐缺失的收集箱归档。现在仅在确认确有遗留问题、停止服务并备份后，手动执行 `npm run db:repair`。该操作按原归档日期恢复；缺少归档标记但正文实际已有内容时可能产生重复，请检查后再执行。
